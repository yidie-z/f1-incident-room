# F1 Incident Room · 争议事件情报室

> 同一场碰撞，两种真相。

一个面向 F1 车迷的争议事件多视角情报室：针对比赛中的碰撞/争议事件，把**事件时间轴、双方阵营表态、FIA 判决书大白话翻译、FastF1 真实遥测图表**整合到一页——每一句话都附原始来源链接。

## 页面结构

- **事件时间轴**：事前局势 → 事发 Team Radio → 双方首次表态 → 领队护犊 → 冷却后的二次表态
- **多视角阵营对峙**：获益方 / 受损方 / 中立专家（布伦德尔、帕尔默等）各自的叙事逻辑
- **"铁证"面板**：FIA 干事判决书原文 + 大白话翻译（为何罚 5 秒而不是 10 秒、依据哪条规则）
- **遥测图表**：速度 / 油门 / 刹车 / 挡位曲线，标出干事认定的接触区

## 本地运行

```bash
npm install
npm run dev        # 打开终端提示的地址（默认 http://localhost:3000）
```

开发服务器下首页底部有「生成新事件页」面板：输入**年份 + 分站 + 两位车手**（支持中文名 / 英文全名 / 三字母代码，如 `2021 蒙扎 汉密尔顿 维斯塔潘`），生成器会自动：

1. 通过 [FastF1](https://github.com/theOehrly/Fast-F1) 拉取官方计时数据（圈速、遥测）；
2. 自动侦测事故圈（圈速暴降 / 名次骤降 / 退赛三重信号投票，可用事故圈参数手动指定）；
3. 生成事件页骨架并热更新到页面。

数据范围：**2018 赛季至今**（FastF1 数据源限制）。骨架生成后，双方发言引语需要人工/AI 按来源核实后补入 `src/data/incidents/<slug>/content.ts`。

## 部署（GitHub Pages）

仓库已内置 GitHub Actions 流水线（`.github/workflows/deploy.yml`）：

1. 把本目录推送到 GitHub 仓库；
2. 仓库 Settings → Pages → Source 选 **GitHub Actions**；
3. 推送到 `main` 分支即自动构建发布，地址为 `https://<用户名>.github.io/<仓库名>/`。

静态部署版为只读（浏览全部已收录事件）；「生成新事件」需要本地开发服务器（依赖 Python + FastF1 环境）。
